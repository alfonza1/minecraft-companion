## Authenticated 26.3 connection recovery

The actual Realm spawned the bot but immediately rejected `serverbound/minecraft:chat_session_update`. A private online-mode official26.3/Java25 server reproduced it. Network debug logging isolated `Malformed public key bytes`, `InvalidKeySpecException` and `extra data at the end`. Prismarine Auth3.1.1's per-line PEM decoder includes the footer when the provider's PEM ends with a newline. Node/OpenSSL and the bridge's Java20 accepted the trailing bytes; the Java25 server rejected them. The worker now parses and re-exports canonical SPKI/PKCS8 DER, checks the public/private pair and expiry, and preserves the provider's certificate signature. No password, token or private key is printed.

The initial authenticated local diagnostic then passed six survival checks, including actual inventory transactions, movement and reconnect, with two successful online session-join callbacks. A passive real-Realm probe subsequently passed45seconds/868physics ticks, health20/food20, no kick, no gameplay task and no model request. It disconnected afterward. The proof is `.git/realm-connection-proof.json`; a receipt of the successful diagnostic's tool output is `.git/verification/realm-onboarding/authenticated-local-success.json`. The maintained command `node scripts/test-modern-bridge.mjs --online-account` repeated this against a new local world, but subsequent attempts failed at Mojang online session verification (`hasJoined` returned an HTML error response on one repeat); they are failures, not passes. Their logs/results are `.git/online-bridge-results.json`. Do not infer certificate correctness or invalidity from that service failure alone; the earlier Java25 decoder reproduction and passive actual-Realm proof are separate evidence. The optional flag makes account/Realm metadata requests but targets the disposable localhost server for gameplay. The default fixture uses no account.

Explicit Realm kicks now stop retries and expose stable credential-free diagnoses. Transient connections must stay up30seconds before their retry budget resets; brief spawn/kick cycles cannot reset it indefinitely. Unit regressions cover both behaviors. Realm version compatibility remains distinct from live connection state in setup; the first-session action checks a saved Realm selection automatically, and an unjoined world is labeled pending rather than an error. Native26.3 remains unreleased in the installed/current npm stack; upstream's data PR still describes incomplete codecs and approximate new-block properties. Translation restrictions remain enforced.
