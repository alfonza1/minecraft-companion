# Local speech

`setup.ps1` creates a Python 3.12 environment under `%LOCALAPPDATA%/MinecraftCompanion/voice-venv`; it does not change the system Python or Minecraft. Models live beside that environment, outside Git. Re-run the script to repair missing dependencies/models.

Default transcription is faster-whisper tiny.en on two CPU threads, INT8, with Silero VAD. Recommended speech is Kokoro Heart, using the full-precision82M CPU ONNX model. Settings offers nine American/British masculine/feminine Kokoro voices and Piper LJ Speech as a lightweight alternative. Selection applies to both desktop and browser responses and persists in SQLite. Windows SAPI is a fallback when neither neural provider is installed. No paid speech API is used. Speech inference loads on demand and exits after each request, trading some latency for low idle memory. The Kokoro session uses two intra-op threads and one inter-op thread to limit contention with Minecraft. Audio requests are at most12MiB and45seconds; microphone audio is piped through RAM into the worker and is never written to disk. Temporary synthesized speech files are deleted on success, failure and cancellation. Audio is never sent to Codex; transcribed text is sent only when the user speaks to the active companion.

`kokoro-models.json` pins the fixed release, sizes and SHA256 hashes of the full-precision ONNX model and NPZ voice vectors. `prepare-kokoro.py` verifies downloads before atomic replacement, outside Git. No pickle checkpoints or remote Python code are loaded. The model assets total about354MB. `requirements-lock.txt` includes kokoro-onnx0.6.1, phonemizer3.4.0 and a private Windows eSpeak-NG loader; it does not install system audio hooks or change CUDA/ROCm. These are quality-focused free local options, not a claim that one voice is universally best; Preview lets the user choose. Previews use a fixed sample, request no microphone permission and make no Codex call. They are blocked while paused.

Settings previews reuse real, full-quality fixed WAV samples under `%LOCALAPPDATA%/MinecraftCompanion/voice-previews`. Speech setup prepares every installed voice once; `node services/voice/prepare-previews.mjs` repairs missing samples. The recommended voice shares Heart's clip. Keys include the fixed text, voice identity and source/model file metadata, so model changes invalidate old audio. Partial writes are atomic, invalid files regenerate, parallel requests share generation, and cancelling the last listener waits for the synthesizer to exit. The cache retains at most 32 WAV files of at most 2MiB each. It contains only the public fixed test phrase, never microphone recordings or conversation speech. Ordinary replies still synthesize fresh text and are not persisted by this cache.

Preview speed is applied by the browser's pitch-preserving playback rate, so changing speed or volume requires no new synthesis. `/api/voice/preview` returns the canonical-speed WAV with `X-Companion-Preview-Speed` and cache-hit headers; the dashboard applies the selected rate. Ordinary `/api/voice/speak` continues using the synthesizer's requested speed. A cold/missing sample still needs one generation; the button shows Preparing and remains cancellable. Prepared samples survive service/app restarts without keeping a Python model resident or running background inference.

The dashboard microphone button requests explicit browser permission. Input/output devices, hold-to-talk, hands-free activity detection, speed, and volume are controlled by the dashboard hook. Browser echo cancellation/noise suppression depend on browser/device support; use headphones. Hands-free activity thresholds are in `apps/desktop-voice/useVoice.ts`. This is utterance-by-utterance speech, not streaming synthesis or realtime simultaneous dialogue.

Saved browser speaker IDs may no longer be authorized in a different browser profile, including the taskbar app's separate WebView2 profile. Settings enumerates currently exposed devices without starting capture, labels an unavailable saved speaker, and offers **Choose audio output** where the browser supports the permission picker. Reauthorizing saves the device ID returned by that browser. **System default** does not require a named-device grant. The desktop bridge has its own speaker selection. See the [audio output permission specification](https://www.w3.org/TR/audio-output/).

If a saved output is denied, missing or fails to switch, the fixed public voice-preview sample uses the system default and displays a notice; it does not overwrite your saved speaker choice or request microphone access. Ordinary conversation audio instead provides recovery instructions and does not silently redirect a private headset conversation. Pause/Stop still prevent delayed device setup from restarting cancelled playback. The desktop host allows delayed audio playback only for its trusted localhost dashboard; microphone permission still uses the normal user prompt, while other origins and permission kinds stay denied. See [WebView2's audio permission](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2permissionkind).

Desktop push-to-talk defaults on when an active Realm session connects or explicitly resumes. **Automatically enable desktop push to talk** and the selected desktop microphone/speakers persist in SQLite. Disable remains off across sessions. Device names and audio host API identify saved devices; numeric indexes are resolved again on startup. A missing or ambiguous saved device stops startup with an actionable error rather than silently redirecting private audio. System default is an explicit selectable option. Browser audio has separate device settings.

Choose **Push-to-talk key → Change key** to change the global shortcut. F8 is the default. Keys F1–F24, letters, digits, Space/Tab/CapsLock, Mouse4/5 and optional Ctrl/Alt/Shift chords share one validated catalog across TypeScript/Node/Python. Escape cancels rebinding, and application-closing chords are rejected. Capture pauses during key selection and restores the saved enabled setting after save or cancel. The native bridge observes only the bound key and modifier states using GetAsyncKeyState; it installs no keyboard hook and does not suppress Minecraft input. It waits for release if the shortcut is already held when enabled. Browser PTT needs focus and stops on blur. Native capture remains PTT-only without browser noise suppression. Pause/stop/disconnect terminate capture and inference; only an explicitly active/resumed connected session restores it automatically. Offline planning never auto-opens a microphone, although its voice can be enabled manually. Physical microphone/headphones and shortcut conflicts still require user testing.

Pause and stop abort the actual backend processes and wait for exit. `/api/voice/cancel` cancels inference; `stopVoice()` additionally closes native capture. Mic recording remains opt-in; paused browser capture stops all media tracks.

In the taskbar app, the main **Enable desktop voice** button starts the global bridge directly and saves the enabled preference. The dashboard and Settings show observed bridge phases and actionable failures. Status messages contain only fixed metadata, never recordings or transcripts. Desktop pressing cancels earlier speech/model work, and the new utterance waits for that cancellation before starting transcription. Cancellation requests use five-second timeouts. A reached local input-token budget is identified separately from account sign-in or hourly request limits: **Settings → AI models & reasoning → Start new token budget** starts another budget at the configured cap without deleting lifetime usage. It does not reset provider/account limits, hourly request limits or billing. Budget renewal makes no model request.

## Observed smoke evidence

On this Windows workstation, SAPI generated a 198,004-byte valid RIFF WAV. Local faster-whisper transcribed its sentence exactly: `Hello friend. Let us collect wood and build a house.` Piper generated a 117,804-byte WAV, and faster-whisper transcribed it exactly as `Yo, I found a pretty good cave over here.` These are synthetic-audio pipeline tests, not proof of the physical microphone/headphones or a Realm session.

PyAV 19 rejected faster-whisper's `metadata_errors` parameter in a real round-trip test. PyAV 16.0.1 is pinned after the corrected round trip passed.

`node scripts/test-voice-options.mjs` generated actual non-silent, distinct PCM output for all nine Kokoro choices and Piper. Kokoro output was24kHz and the short fixed cave sentence took about3.1–4.1seconds per cold request on this workstation; Piper took4.6seconds in that run. Quality preference and physical output are not established by waveform checks. The local TTS→Whisper round trip and the actual HTTP/UI Kokoro preview also passed. Browser tests used Chromium's synthetic microphone and explicitly empty transcription fixtures to verify F8/chord hold/release, reset stopping capture, and pause without recording a real microphone or making model calls.
